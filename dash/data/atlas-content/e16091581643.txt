# Log Retention Standard

> Routine logs >24h deleted, failures preserved 90 days, protected records never touched. Daily summaries. Governance standard, not just disk management.

**Established:** 2026-08-03
**Decision:** `knowledge/decisions/2026-08-03-log-retention-standard.md`
**Status:** Active

## Purpose

Ensure Atlas remains reliable, auditable, and operable by retaining what matters and removing what does not. This is not a disk-space measure — it is a governance standard.

## Scope

This standard applies to all automated operational logs generated by Atlas cron jobs.

## Policy

### 1. Routine Operational Logs

High-frequency cron outputs are classified as routine operational logs. These include:

| Job ID | Name | Frequency |
|--------|------|-----------|
| `203f3a6cfd56` | quotes-pulse-phase2 | Every 1 min |
| `2d4a9ff4f06b` | inbox-pulse-phase2 | Every 3 min |
| `51474e46f382` | follow-up-autopilot | Every 5 min |
| `d0cdcda5b237` | inbox-watchdog-phase1 | Every 3 min |
| `20810e75d779` | quotes-watchdog-phase1 | Every 1 min |

**Rule:** Routine successful outputs older than 24 hours are automatically deleted.

### 2. Failure and Warning Logs

Any cron output file containing actual operational errors (not prompt/instruction text) is classified as a failure record.

**Detection:** Content AFTER the `## Response` marker is scanned for: `error`, `exception`, `traceback`, `failed`, `timeout`, `unable to`, `could not`, `refused`, `denied`, `aborted`, `not found`, `permission denied`, `connection reset`.

**Rule:** Failure logs are retained for a minimum of 90 days, or until the underlying issue is resolved and documented.

### 3. Protected Records — Never Purged

The following are governed business records, not disposable technical logs. They are never subject to automated deletion:

- Send Evidence Records
- Change Requests
- Lessons Learned (`learnings/`)
- Decision records (`knowledge/decisions/`)
- Customer communication history (`drafts/`)
- Approval records
- Experiment results (`knowledge/experiments/`)
- Security incidents
- Memory entries (`memory/`)
- Trust Framework documents (`Agent/`)
- Any record required to explain what Atlas did and why

### 4. Daily Operational Summaries

Before routine logs are deleted, meaningful information is consolidated into daily summaries stored at `logs/daily-summaries/YYYY-MM-DD.json`.

Each summary contains per-job:
- Number of runs
- Successful runs
- Failures
- Warnings
- Emails processed
- Quotes processed
- Replies detected
- Anomalies identified

### 5. Storage Health Monitoring

Storage health is monitored every 6 hours via `bin/storage-health.py`.

Thresholds:
- **Warning:** Disk > 85%
- **Critical:** Disk > 92%
- **Abnormal growth:** > 5% per day

Storage health is surfaced to Headquarters only when thresholds are breached.

### 6. Safe Failure

The retention script (`bin/log-retention.py`) enforces:
- Only deletes from explicitly approved directories (`/root/.hermes/cron/output/`)
- Never follows symlinks outside approved paths
- Never touches protected globs
- Runs in dry-run mode via `--dry-run` flag for verification
- All protected records remain untouched regardless of age

## Execution

- **Daily retention:** Cron `c68ae5970e89` at 20:30 ACST (11:00 UTC)
- **Storage monitoring:** Cron `506c5b3ae6bf` every 6 hours
- **Manual:** `python3 bin/log-retention.py --dry-run` (preview), `python3 bin/log-retention.py` (execute)
