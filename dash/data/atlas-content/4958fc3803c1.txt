## New observations for the series

1. **The detection note mislabels its own timeline.** It records the guard run as "2026-10-07 07:50 ACDT", but the file mtimes are `07:50 UTC` = **18:20 ACST**. This is the same UTC-mtime-read-as-local error the series already falsified once (falsified hypothesis #1). Detection latency is therefore **~11.9 h**, not 1.7 h. Corrected here; future records must convert from the `stat` offset before naming a clock time.
