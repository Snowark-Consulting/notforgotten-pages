# Website Intelligence — Operating Standard

> Google Analytics as evidence source for business decisions, not another dashboard.

**Established:** 2026-07-25  
**Source:** Strategic Directive from James Hardstaff  
**Status:** Active

## Core Principle

Google Analytics is not another dashboard. It is a source of evidence for the Not Forgotten operating system. The objective is not to report website metrics — it is to help make better business decisions.

Every piece of data must answer: **"What should we do because we now know this?"**

## Weekly Intelligence Report

### Structure (one page, coffee-readable)

| Section | Content |
|---|---|
| **What changed** | Difference from last week. Not all metrics — only the deltas that matter. |
| **Why it might have changed** | Evidence where possible. Theories clearly labelled as hypotheses. |
| **Why it matters** | Impact on leads, trust, conversions, or positioning. |
| **One recommended action** | Practical, specific. Never "monitor this." Always an experiment or decision. |

### Rules

- If a report doesn't help make a better decision, it isn't valuable.
- No information for the sake of information.
- Every website change becomes an experiment — measure the outcome.
- Close the loop: report whether changes achieved their intended outcome.

### Key Questions to Answer

- Which pages create the highest quality enquiries?
- Which industries spend the longest on the website before contacting us?
- Which marketing channels create paying clients, not just visitors?
- Which website changes increase demo bookings?
- Which content builds the most trust?

**Method caveat (important):** `scripts/ga4-intel.py` builds its weekly "users" figure by summing per-day `activeUsers`. That is a day-sum, not unique weekly users — a visitor active on three days counts three times. Always compare day-sum against day-sum; never present the figure as "unique visitors". For true weekly uniques, request dimension `isoYearIsoWeek` (see `scripts/ga4-deep-dive.py`).

**Script pitfall (2026-10-04):** a stray `/tmp/inspect.py` left by an earlier job shadowed the stdlib `inspect` module and broke every Python run from `/tmp` with `AttributeError: module 'inspect' has no attribute 'signature'`. Never place scratch scripts in `/tmp`; write them to `~/.hermes/scripts/`. Contained 2026-10-04 by renaming the file to `/tmp/DISABLED_inspect.py.bak`.

**Timezone pitfall (2026-10-04):** `ga4-intel.py` and `ga4-deep-dive.py` both hardcoded `timezone(timedelta(hours=9, minutes=30))`. ACST→ACDT crossed at 02:00 on 4 Oct 2026, so from that moment both emitted timestamps an hour stale and mislabelled (the run printed `20:30:57+09:30` against a wall clock of 21:30 ACDT), and the reporting window itself can be misdated if the job runs late evening. Both now use `ZoneInfo("Australia/Adelaide")`; re-verified `+10:30` with identical week windows. Same class as the same-day fix to `overnight-hq-regen.py`; 60+ further hardcoded offsets remain under `scripts/`/`bin/`, including `canonical-send.py` (infra-owner action, not touched from a report job). Rule: never satisfy the "use Adelaide timezone" standard with a fixed UTC offset — a DST transition invalidates them all at once.
