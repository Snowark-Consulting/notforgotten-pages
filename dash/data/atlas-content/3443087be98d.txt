## APP 11 — Security and Destruction/De-identification

**Requirement:** Take reasonable steps to protect personal information, and to destroy or de-identify when no longer needed.

| Element | v1.0 Coverage | Status |
|---|---|---|
| Security safeguards described | Section 9: encryption, access controls, credential management, provider security, regular review | ✅ |
| Honest about limitations | "No online system can guarantee complete security" | ✅ |
| Retention periods defined | Section 12: specific periods per data category | ✅ |
| Deletion described | "We take steps to delete or de-identify" | ⚠️ Aspirational — automated retention not yet implemented |
| Credential security statement | "API keys and access tokens stored in secured credential stores, not in code or logs" | 🔴 SEC-001 and IA-2026-001 unresolved |

**Gap:** SEC-001 (GitHub PATs in URLs) and IA-2026-001 (GA4 key in logs) contradict the credential security statement. **Resolution:** Resolve before publication.

**Gap:** Automated retention not yet implemented. **Resolution:** The policy currently claims automated processes exist. Either implement before publication or adjust language to be honest about current state. **Recommended:** "We are implementing automated retention processes. Currently, deletion requests are handled manually on request."
