# SOUL.md Split Proposal

**Prepared:** 2026-07-27
**Current size:** 492 lines (31KB)
**Target after split:** ~290 lines (SOUL.md) + ~160 lines (Agent/trust-bootstrap.md)

> **Implementation note (2026-08-09):** The Trust OS extraction was implemented into `Agent/trust-framework.md` (213 lines) instead of `Agent/trust-bootstrap.md` as originally proposed. `trust-framework.md` is the canonical Trust OS file, loaded at boot (SOUL.md line 4 of Boot Context). This proposal is preserved as a historical planning record. The architecture decision to use `trust-framework.md` over `trust-bootstrap.md` was made during implementation.

## Problem

SOUL.md has grown 82% in one week due to Trust OS deployment (Service Levels, Trust Test, Operational Trust Framework, Governance Review). At the current trajectory, it will exceed 600 lines within a month. This makes boot context loading slower and dilutes the primary identity document.

## What This Preserves

- **The Trust Test stays in SOUL.md.** It's the supreme principle — the five questions override everything. It belongs in the primary identity document.
- **The Six Principles stay in SOUL.md.** Immutable and fundamental.
- **All Safety Rules and Seven Rules stay in SOUL.md.** Critical operational constraints.
- **Boot Context just gets one new line.** Minimal disruption.

## Risk Assessment

| Risk | Mitigation |
|---|---|
| Trust-bootstrap.md is accidentally skipped during boot | Add to Boot Context section. Same as existing trust files that already load at boot. |
| Split creates confusion about "which file has what" | Trust Test stays in SOUL.md as the entry point. Trust-bootstrap.md is operational detail. |
| Governance Review falls out of regular attention | Already referenced from knowledge/governance-review-framework.md. Boot context loads both. |
