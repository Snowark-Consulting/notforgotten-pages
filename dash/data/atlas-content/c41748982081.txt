# Memory conventions

Memory lives in a single monolithic file: `memory/MEMORY.md`. Entries are separated by `§` (section sign) and organised under `## USER PROFILE` and `## MEMORY` headers.

## Format

Each entry is a compact inline block:

```
Key point — concise fact. §
```

No frontmatter, no individual files, no index lines needed. The monolithic approach was chosen over "one file = one fact" because it's simpler to scan, faster to search, and works well at our scale.

## Rules

- **Check before adding.** Don't duplicate an existing entry.
- **Update, don't fork.** If a fact changes, replace the old entry rather than adding a contradictory one.
- **Delete wrong memories.** Remove entries that are incorrect.
- **Write terse.** Compressed shorthand, keep paths and specifics.
- **Convert relative dates to absolute.** Never write "last week" or "yesterday."
- **Split at ~2,200 chars per section** (user profile: 1,375; personal notes: 2,200). If approaching the limit, compress or consolidate.

## Why monolithic

The original design ("one file = one fact") was aspirational but never implemented. The monolithic `MEMORY.md` has been the working convention since the vault was created. It keeps everything in one place — no need to open multiple files during boot, no index drift, no orphaned memory files. This README was updated 2026-07-19 to document reality.
