# Decision: Single Source of Truth Principle for Client-Facing Communications

**Status:** Made
**Date:** 2026-08-01
**Decision by:** James Hardstaff
**Atlas Challenge:** None — Atlas agrees. This is the correct fix.

## Context

On 2026-08-01, three follow-up emails were sent to QPaint customers that violated the approved voice standard. The emails omitted introductions, used "following up" language (explicitly forbidden), and sounded robotic.

Root cause analysis revealed the autopilot script contained its own hardcoded email templates, independent of the approved canonical template at `references/qpaint-recovery-introduction.md`. The Voice Review gate checked surface-level rules ("contains the word pricing?") rather than verifying against the canonical source. The gate returned PASS and Atlas trusted it.

Two sources of truth existed: one approved, one operational. The operational one was wrong.

## Decision

### 1. Single Source of Truth Principle

For every client-facing communication, there must only ever be one canonical template.

- Automations, scripts, workflows, and cron jobs must never contain their own copy of an email body.
- All outbound emails must be generated by loading the canonical template at send time.
- If the canonical template is updated, every automation automatically uses the updated version.
- No duplicated templates. No hardcoded email bodies. No parallel versions.

### 2. Canonical Templates Directory

All client-facing email templates live in `knowledge/canonical-templates/`. Each template is:
- Versioned (v1, v2, etc.)
- Checksummed (SHA256 over the template body)
- Registered in `INDEX.md`
- Loaded at send time by `scripts/canonical_template.py`

### 3. Canon Verification Gate

Before any client-facing send, four questions must be answered with evidence:

1. Which canonical template is being used?
2. What version is it?
3. Does the generated email match the template? (checksum verified)
4. If variables differ from template, are they the only differences?

A "no" to any question = hard stop. No send.

### 4. "Never Trust a Green Tick"

New operating principle: The purpose of a gate is not to make us feel confident. The purpose of a gate is to prove the system is behaving exactly as intended. A green "PASS" should mean "verified against evidence", not "surface-level checks passed." Trust the evidence behind the green tick.

## Implementation

- `knowledge/canonical-templates/INDEX.md` — Registry of all canonical templates
- `knowledge/canonical-templates/qpaint/recovery-introduction-v1.md` — QPaint Recovery Introduction v1
- `scripts/canonical_template.py` — Template loader, checksum verification, Canon Verification Gate
- `scripts/follow-up-autopilot.py` — Replaced all hardcoded templates with `load_template()` calls

## Precedents Set

- No script may contain an email body. All bodies come from canonical templates.
- Every new client onboarded will have their templates in `knowledge/canonical-templates/{client}/`.
- Every template is versioned. Old versions are never deleted, only superseded.
- The SHA256 checksum prevents silent modification.
