## Services

| Service | What it does | Managed by |
| ------- | ------------ | ---------- |
| hermes-gateway | channel gateway, inbound and outbound messages (Telegram) | Hermes cron scheduler |
| gateway-supervisor | standalone watchdog daemon — relaunches the gateway if it dies (crash OR planned-restart exit 75) | double-fork daemon (`scripts/gateway-supervisor.py`); start manually after reboot |

> **Gateway exit code 75 = planned restart (EX_TEMPFAIL), NOT a crash.** The gateway exits 75 on any restart request (`hermes gateway restart` / SIGUSR1) and expects a service manager (systemd) to revive it. This box has NO systemd and NO crond, and the Hermes cron scheduler is embedded in the gateway (it dies with it) — so before `gateway-supervisor.py` was added (2026-08-29), any exit-75 or crash left the gateway down until manual restart (e.g. the 8.5h memory SIGKILL of 28 Aug and the 36-min exit-75 of 29 Aug). Manage it: start `python3 scripts/gateway-supervisor.py`; stop `kill $(cat state/gateway-supervisor.pid)`; log `logs/gateway-supervisor.log`; crash-loop alert marker `state/gateway-crash-loop-alert`. Loop guard: gives up after 5 rapid failures (death within 120s of launch) in a row.
