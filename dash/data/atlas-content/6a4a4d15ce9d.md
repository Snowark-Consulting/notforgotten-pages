## Processing Rules

1. Read each unread email using the Gmail API (google_api.py)
2. MARK AS READ immediately — remove UNREAD label BEFORE summarising. This closes the race-condition window with Phase 1: if you summarise first, Phase 1 will find the email still unread on its next 60s tick and Phase 2 will process it twice. Mark-read-first prevents duplicates.
3. **QUOTE INTAKE CHECK** — run `python3 scripts/quote-intake.py <MESSAGE_ID>` on every email:
   - `status: "not_a_quote"` → proceed to normal summary (step 4)
   - `status: "prospect_to_client"` → **AUTO-PROCESS:** move Prospect → Client in Airtable, create Quote record. Notify James with: "📬 **Quote received** — {sender_name} ({sender_email}) moved from Prospects to Clients. Quote created in Airtable."
   - `status: "existing_client"` → **AUTO-PROCESS:** create Quote record only. Notify James with: "📬 **Quote received** — {sender_name} ({sender_email}) is an existing client. New quote created in Airtable."
   - `status: "unknown_sender"` → **FLAG IMMEDIATELY:** notify James with: "⚠️ **Unknown sender sent a quote** — {sender_name} ({sender_email}) is not in Prospects or Clients. Subject: {subject}. I need your direction before I can process this."
   - If the script fails/errors, fall through to normal summary (step 4) and log the error
4. For each non-quote email, craft a summary for Telegram:
   - **Sender name** — *Subject*
   - One sentence of what it is
   - Then a recommendation in one of these forms:
     - **From James:** "Would you like me to draft a reply / queue this in Airtable / start the follow-up sequence?"
     - **From anyone else:** "Would you like me to draft a reply / flag this for James / log this somewhere?"
   - If it's just test noise or FYI: "No action needed — just letting you know."
5. Never assume permission for non-quote emails. Always ask. "Would you like me to..." is the standard.
6. Post summary to Telegram group with heading: **📬 Inbox — <count> new**

### Quote intake auto-processing rules

When the quote-intake script returns `prospect_to_client` or `existing_client`, the agent MUST:

1. Read the `extracted_text` from the script output
2. Parse the structured data using the LLM (business name, customer details, quote value, scope summary)
3. Call quote-intake.py's functions (or direct Airtable API) to:
   a. For `prospect_to_client`: create Client record, mark Prospect as Won, create Quote
   b. For `existing_client`: create Quote record only
4. Create a Message record for the inbound email (Direction: Inbound, Channel: Email, Purpose: "Reply received")
5. Notify James via Telegram with what was done

The `quote-intake.py` script does the detection and cross-reference. The agent handles the data extraction and Airtable mutations based on the script's guidance.

## Tone rules

- Proactive but permission-seeking. "Would you like me to..." not "I'll..."
- James's emails: offer specific, useful next actions (draft, queue, follow up)
- Everyone else: offer to draft a reply or escalate — never assume action
- One recommendation per email. Keep it tight.

## Posting to Telegram

After processing, send the summary via Telegram Bot API. Read the bot token from the environment:
```
export $(grep TELEGRAM_BOT_TOKEN /root/.hermes/.env | cut -d= -f2-)
```

Then post:
```
curl -s -X POST "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendMessage" \
  -d chat_id=-1003880645651 \
  -d parse_mode=Markdown \
  -d text="YOUR SUMMARY"
```

The agent's final response should be empty — the Telegram post IS the output.

## Gmail API reference

All commands via:
```
GAPI="/roo...  python3 /root/.hermes/skills/productivity/google-workspace/scripts/google_api.py"
```

Search: `$GAPI gmail search "is:unread" --max 10`
Get: `$GAPI gmail get <MESSAGE_ID>`
Mark read: `$GAPI gmail modify <MESSAGE_ID> --remove-labels UNREAD`

## Pitfalls

- `gog gmail mark read` (space) silently fails — always use `mark-read` (hyphen) with gog, or the Gmail API `modify --remove-labels UNREAD`
- `newer_than` only accepts d/m/y — never use for sub-day windows
- Always verify the UNREAD label is gone by re-checking labels after marking
