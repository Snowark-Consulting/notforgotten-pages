## 2026-08-06 — PandaDoc SPA invisible to DOM queries; Accessibility API required

**Confidence:** high
**Contested:** false
**Symptom:** PandaDoc share pages are React SPAs that render content via contenteditable `textbox` elements. Standard DOM queries return empty: `document.body.innerText` = `""`, `document.body.textContent` = `""`, `document.querySelectorAll('table tr')` = `0`, `document.querySelectorAll('[contenteditable="true"]')` = `0`. The `pandadoc-extract.py` v1 returned "No text extracted from page" for all PandaDoc URLs.

**Cause:** PandaDoc's React render pipeline creates a virtual DOM that the accessibility tree sees but standard DOM traversal does not. The content is visually rendered but programmatically invisible to `Runtime.evaluate`. Additionally, `browser_console` targets `chrome://new-tab-page`, not the PandaDoc tab — `document.title` returns `"New Tab"`.

**Fix:**
1. `pandadoc-extract.py` v2 uses `Accessibility.getFullAXTree` (CDP) as primary extraction method, with `document.body.innerText` as fallback.
2. AX tree splits compound values across separate nodes — parser handles multi-line names ("Manohar" / "Ganji" / email), dates ("Date:" / "03 / 08 / 2026"), and values ("Total" / "$13,860.00").
3. Address extracted via street-pattern heuristic (title line filter + de-duplication).
4. Quote number extracted from document title pattern (`^(\d{5})\s*-\s*`).
5. Page loading detected by polling AX tree until "Connecting" text disappears and node count exceeds 100.
6. `PUT /json/new` does NOT populate the AX tree — must use `browser_navigate` or `Page.navigate` on existing tabs.
7. Deduplication required: AX tree has identical text in multiple node types (StaticText + InlineTextBox).

**Validation:** 6/6 fields verified across 2 PandaDoc quotes (NF-QPAINT-43054, QPAINT-43016). Test 3 token expired (expected — PandaDoc share links are time-limited).

**Principle:** A failed extraction method does not mean the data is unavailable. When rendered content is inaccessible through the DOM, inspect the accessibility tree and network layer before escalating.

**Files modified:**
- `scripts/pandadoc-extract.py` — v2.0.0, AX-tree primary extraction
- `skills/notforgotten/quote-intake/references/pandadoc-intake-pattern.md` — updated extraction docs

## 2026-07-02 — Skills need dual-path redundancy: Registry + SOPs, not just the skills-list scanner

## 2026-07-01 — Always Use Adelaide Timezone

**Symptom:** Command Centre dashboard showed dates in UTC (e.g., "2026-06-30 23:11") instead of Adelaide time.  
**Cause:** `datetime.datetime.now()` was called without timezone specification in dash-update.py, dash-live-refresh.py, pipeline-data.py, on-error handler, and quote-intake.py. The orgo server runs UTC.  
**Fix:** All scripts now use `ZoneInfo("Australia/Adelaide")` — pattern: `from zoneinfo import ZoneInfo; ADELAIDE = ZoneInfo("Australia/Adelaide"); datetime.now(ADELAIDE)`.  
**Exception:** For Airtable API timestamps with `Z` suffix (e.g., "Sent at"), convert to UTC first: `datetime.now(ADELAIDE).astimezone(timezone.utc)`.  
**Pattern protection:** session-activity hook already had this correct — other scripts should follow its pattern. New scripts must use Adelaide timezone from day one.

## 2026-06-30 — Cron --script paths resolve relative to scripts/, not vault root (corrected from 2026-06-29 misdiagnosis)
**Symptom:** Pipeline data refresh cron (251c65e49027) with `--script bin/pipeline-data.py` failed with "Script not found: /root/.hermes/scripts/bin/pipeline-data.py". Vault graph rebuild (ed054f2de399) with `--script scripts/vault-graph.py` failed with "Script not found: /root/.hermes/scripts/scripts/vault-graph.py".
**Cause:** The 2026-06-29 pitfall was wrong. Hermes cron does NOT resolve `--script` paths from vault root (~/.hermes/). It prepends `scripts/` to every script path. `bin/pipeline-data.py` → `scripts/bin/pipeline-data.py`. `scripts/vault-graph.py` → `scripts/scripts/vault-graph.py`.
**Fix:** Scripts in `scripts/` use bare filename (`dashboard-update.py`). Scripts in `bin/` use `../bin/name.py` or create symlink at `scripts/bin/name.py → ../../bin/name.py`. Verify: `test -f ~/.hermes/scripts/<script-path>`. Corrected growth-operations skill pitfall.

## 2026-06-25 — Gmail token `expiry` field stored as int crashes `from_authorized_user_file`
**Symptom:** Gmail API `google_api.py gmail search` crashed with `AttributeError: 'int' object has no attribute 'rstrip'` in `Credentials.from_authorized_user_file()`. The inbox watchdog (Phase 1) produced empty output — appearing to mean "no mail" — but was actually crashing silently on every 60s tick.
**Cause:** `google_token.json` had `"expiry": 3599` (an int, the `expires_in` value) instead of an ISO 8601 datetime string like `"2026-06-25T08:17:03Z"`. The Google OAuth library expects `expiry` to be a string and calls `.rstrip("Z")` on it. This corrupted token was likely produced by a failed/partial token write.
**Fix:** Patch `expiry` to `"1970-01-01T00:00:00Z"` (already-expired timestamp). On next API call, `get_credentials()` sees `creds.expired == True`, uses `refresh_token` to get a fresh token, and writes the correct ISO datetime string back to the file. One-liner: `python3 -c "import json; d=json.load(open('/root/.hermes/google_token.json')); d['expiry']='1970-01-01T00:00:00Z'; json.dump(d, open('/root/.hermes/google_token.json','w'), indent=2)"`. After fix, verify with: `python3 -c "import json; d=json.load(open('/root/.hermes/google_token.json')); assert isinstance(d['expiry'], str)"`.

## 2026-06-23 — Inbox pulse double-post: race condition between Phase 1 poll and Phase 2 mark-read
**Symptom:** Email update appeared twice in Telegram. Phase 2 summarised and posted, but Phase 1 found the same email still unread on its next 60s tick, causing Phase 2 to process it again.
**Cause:** Phase 2 takes 30-45s to boot full identity (6 files), read email, and summarise — all before reaching the mark-as-read step. Phase 1 runs on the 60s boundary and finds the email still unread during that window.
**Fix:** Reorder processing in pulse-bootstrap.md: mark-as-read immediately after reading, BEFORE summarising. This closes the window to under 1 second. The new order is: read → mark-read → summarise → post.

## 2026-06-22 — Gmail `newer_than:15m` = 15 MONTHS, not minutes
**Symptom:** Gmail searches using `newer_than:15m` returned entire unread backlog instead of the last 15 minutes.
**Cause:** Gmail's `newer_than:` operator only accepts `d` (days), `m` (MONTHS), `y` (years). There is no minute unit. `newer_than:15m` silently widens to 15 months.
**Fix:** Never use `newer_than` for sub-day windows. Filter by `internalDate` in code after fetching. Use `newer_than:1d` as a coarse pre-filter, then narrow with `internalDate` epoch-ms comparison.
**Source:** Cross-pollinated from AFS Vault LRN-20260615-006 (Gary's system).

## 2026-06-22 — Gmail `batchModify` returns 204 with empty body; json.load crashes
**Symptom:** Gmail API `POST /messages/batchModify` appeared to fail with JSON parse error, but the label change had actually succeeded server-side.
**Cause:** `batchModify` returns HTTP 204 with an empty body. `json.load()` on empty string raises `Expecting value`. The error was a parse failure, not an API failure.
**Fix:** Check response body before parsing: `raw = r.read(); return json.loads(raw) if raw else {}`. For 204-returning endpoints, verify by re-fetching labels rather than retrying.
**Source:** Cross-pollinated from AFS Vault LRN-20260618-001 (Gary's system).

## 2026-06-22 — Piping stdout (`| tee`) kills interactive agent sessions
**Symptom:** Agent launched via `tmux new-session ... | tee log` died instantly with "Input must be provided through stdin or as a prompt argument when using --print."
**Cause:** Piping stdout makes the process see a non-TTY. Native agent binaries switch to headless `--print` mode and exit immediately when they detect no TTY. The `tee` success echo runs unconditionally after `tmux new-session` returns, so the restart log falsely shows success.
**Fix:** Never pipe interactive agent stdout. Use `tmux pipe-pane -o -t <session> 'cat >> log'` after launch to capture output non-intrusively. Verify the process actually lived: `tmux ls` and check the pane log for immediate error lines.
**Source:** Cross-pollinated from AFS Vault LRN-20260616-001 (Gary's system).

## 2026-06-22 — High-frequency cron in main session burns tokens on context reloads
**Symptom:** Cron jobs firing every 5-10 minutes reload full agent context (~30k+ tokens) each tick — expensive and unnecessary for polling/monitoring tasks.
**Cause:** Main-session cron jobs load all boot context files on every invocation. For a job firing every 10 minutes, that's 144 full context loads per day.
**Fix:** Use isolated sessions for high-frequency utility crons. Use `no_agent: true` with a script for pure polling (like the Atlas Watchdog). Reserve main-session loading for tasks that genuinely need full context.
**Source:** Cross-pollinated from AFS Vault LRN-20260408-002 (Gary's system).

## 2026-06-22 — macOS cron cannot access Keychain; use LaunchAgents for credential-dependent jobs
**Symptom:** Scheduled tasks needing OAuth/Keychain-stored credentials fail with "Not logged in" when run via crontab.
**Cause:** macOS cron runs outside the user's login session and cannot access the Keychain. LaunchAgents (`~/Library/LaunchAgents/`) run inside the login session and have Keychain access.
**Fix:** All scheduled tasks that need credential access must use LaunchAgents or launchd services, not crontab. For Hermes cron (which runs inside the agent process), this is handled by the gateway — but external scripts triggered by cron should use launchd.
**Source:** Cross-pollinated from AFS Vault LRN-20260410-002 (Gary's system).

## 2026-06-22 — Hardcoded versioned binary paths break silently when versions change
**Symptom:** Scripts referencing `/path/to/node/v24.4.0/bin/tool` failed silently after the version directory was cleaned up. LaunchAgents and heartbeat scripts all broke simultaneously.
**Cause:** Version-manager directories (nvm, pyenv, asdf) are ephemeral. Hardcoding a specific version path creates a time bomb that fires when old versions are pruned.
**Fix:** Use version-independent paths: `~/.local/bin/claude`, `/usr/local/bin/python3`, or rely on PATH lookup. Never hardcode versioned directories in plists, cron jobs, or scripts. When a binary must be pinned, use a symlink at a stable path.
**Source:** Cross-pollinated from AFS Vault LRN-20260430-001 (Gary's system).

## 2026-06-22 — Automated launchers echo success unconditionally; verify the process lived
**Symptom:** A LaunchAgent/cron reported success (echo "started OK") but the agent process had died in under 1 second. Went undetected for days.
**Cause:** Launcher scripts run `tmux new-session` or `nohup` and then unconditionally echo success. The success echo doesn't mean the child process survived — only that the launcher finished.
**Fix:** After launching, verify: check process table, read the session log for immediate errors, confirm the PID exists. A "started" echo is a launch confirmation, not a liveness proof. For critical agents, add a watchdog that verifies the process is alive, not just that it was launched.
**Source:** Cross-pollinated from AFS Vault LRN-20260615-001 (Gary's system).

## 2026-06-22 — zsh does NOT word-split unquoted variables like bash
**Symptom:** `for p in $pairs` loop ran ONCE with the entire string when run in zsh, causing data corruption (wrong IDs paired together).
**Cause:** zsh (unlike bash) does not word-split unquoted scalar variables by default. The loop variable receives the entire string as one item.
**Fix:** For any multi-record loop where a mismatch would corrupt data, do the iteration in Python, not shell. If shell is unavoidable in zsh, force splitting with `${=var}`. Always read back the artifact to confirm correct values before moving on.
**Source:** Cross-pollinated from AFS Vault LRN-20260617-004 (Gary's system).

## 2026-06-22 — Discord/Cloudflare blocks default Python User-Agent (HTTP 403 code 1010)
**Symptom:** Direct API calls to Discord via Python `urllib` returned HTTP 403 with Cloudflare error code 1010 — a banned browser signature, not an auth failure.
**Cause:** Discord's API requires a descriptive User-Agent header per their docs. Python's default `Python-urllib/3.x` gets rejected at Cloudflare's edge.
**Fix:** Set an explicit `User-Agent` header on all direct HTTP API calls: `User-Agent: AppName (url, version)`. This applies to any service behind Cloudflare, not just Discord.

## 2026-06-20 — Supabase anon key is INSERT-only; use service_role for reads
**Symptom:** Querying `client_responses` with the anon key returned `[]` (empty array) even though records existed.
**Cause:** The Supabase RLS policy on `client_responses` allows the anon key to INSERT but not SELECT. Reads require the service_role key.
**Fix:** Use `SUPABASE_SERVICE_ROLE_KEY` for read queries against `client_responses`. The anon key is for form submissions (client-side); the service_role key is for backend reads (Winston queries). Both are in `~/.hermes/.env`.

## 2026-06-18 — Git case sensitivity on macOS
**Symptom:** `git clone` on macOS (case-insensitive filesystem) failed to find `Agent/Skills/` when searching for `Agent/skills/`. Files existed on remote but weren't found locally.
**Cause:** macOS APFS is case-insensitive by default. Git stores paths as-is from remote (case-sensitive), but local searches using `find` or `ls` with wrong case won't match. When a repo is cloned, files at `Agent/Skills/` are accessible at both `Agent/Skills/` and `Agent/skills/` locally, but programmatic searches with exact-case patterns fail against different-case patterns.
**Fix:** When searching cloned repos for Hermes agent files, try both `Agent/Skills/` (capital S, as stored in many AFS repos) and `Agent/skills/` (lowercase, as used locally). Use `find -iname` for case-insensitive searches. When accessing via GitHub API, use exact case as stored on remote.

## 2026-06-30 — Epoch-zero Gmail `expiry` flagged as broken by cron; token was fine
