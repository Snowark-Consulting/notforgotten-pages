## 2026-09-20 — Stray `/tmp` module shadows the stdlib and breaks GA4 tooling
**Confidence:** high
**Contested:** false
**Symptom:** Any Python script that imports `google.analytics.data_v1beta` (or anything reaching `urllib3`) crashes with `AttributeError: module 'queue' has no attribute 'LifoQueue'` when run from `/tmp`. Importing `scripts/ga4-intel.py` by path also fails. A second symptom: running a script from `/tmp` printed unrelated prepare-ahead prospect output before the traceback.
**Cause:** A leftover `/tmp/queue.py` (dated 2026-09-13) shadows the Python standard library `queue` module, because the script's own directory is first on `sys.path`. `urllib3/connectionpool.py` does `from queue import LifoQueue` and picks up the stray file.
**Fix:** Never run multi-step Python from `/tmp`. Use a dedicated clean working directory: `mkdir -p /root/ga4work`, copy the script there, and run with `cd /root/ga4work && python3 script.py`. Also avoid `sys.path.insert(0, '/root/.hermes/scripts')` for ad-hoc work. Quick diagnostic: `ls /tmp/*.py` to check for shadowing modules.

## 2026-09-20 — The email signature is owned by Gmail, not by `james_signature.json`
**Confidence:** high
**Contested:** false
**Symptom:** Any edit to `james_signature.json` (e.g. to add UTM parameters to the website link) is silently reverted.
**Cause:** `bin/sync-james-signature.py` runs on a weekly cron, reads the authoritative signature from the Gmail API (`users/<addr>/settings/sendAs`) and overwrites `james_signature.json` with it. The local file is a cache, not the source.
**Fix:** Change the signature in **Gmail settings** for `james@notforgotten.com.au`, then run `python3 bin/sync-james-signature.py` to propagate. Propagation chain: Gmail `settings/sendAs` → `bin/sync-james-signature.py` → `james_signature.json` → `scripts/sig_assembly.py: assemble_html()` → outbound HTML. Note `scripts/canonical-send.py` (the declared "single authority" for customer email) sends `text/plain` with `MIMEText` and never appends the signature at all, so a signature-level fix does not cover that path.

## 2026-09-21 — Value QPaint tick-box OPTION blocks by checkbox state, not by label
**Confidence:** high
**Contested:** false
**Symptom:** Two QPaint documents from the same day and template needed opposite valuation treatments; the label alone ("OPTION 1. PART EXTERNAL", "All options not selected") pointed the wrong way for one of them.
**Cause:** Optional scope blocks render as real `<input type="checkbox">` elements. Inclusion is decided by the checked state. A checked block renders a populated Subtotal/GST/Total row and belongs in `Deal Value`; an unchecked block renders `$0.00`/`$0.00`/`$0.00` and is excluded.
