- **A retried API call is not a hardened gate — the OAuth refresh POST is a second single-shot failure point.** `james-watchdog-gate.py` exited 1 at 07:20 ACST with `token refresh failed — <urlopen error [Errno 32] Broken pipe>`: 17 Sep had added retries to `api_get()`, but `get_token()` was still one shot, so one dropped connection on the POST to `oauth2.googleapis.com/token` produced a false "script failed" wake. It happens **first**, before any API call, so query-layer retries can never cover it. **No mail was missed** — the gate exits before the unread query and before the seen-state write (fail-OPEN, nothing consumed), and an independent raw-HTTP read confirmed 2 unread, both previously processed, 0 new. Applied to all three gates after checking each refresh path rather than assuming; the curl one needed its own shape (parse `%{http_code}`, retry `403|429|5xx|empty`). Verified by stub server on the bash gate (503 x2 then 200 → clean `{"wakeAgent": false}`; HTTP 400 → one ERROR line, exit 1, 0.12 s, no retry storm) and monkeypatched-transport tests on both Python gates. → `learnings/cards/gmail.md`, `scripts/james-watchdog-gate.py`, `scripts/quotes-watchdog-gate.py`, `scripts/inbox-watchdog-gate.sh`
- **All three pulse gates now retry transient Gmail quota errors — the atlas@ gate hardened against a stub, not in passing.** `inbox-watchdog-gate.sh` (atlas@, the primary customer mail path, deliberately left single-shot on 17 Sep) got the same treatment as the two Python gates: a 4-attempt loop with linear backoff covering 403/429/500/502/503/504 and empty-response network failures, parsing the HTTP code out of `curl -w '\n%{http_code}'`, and **failing fast (single ERROR + exit 1) on any other non-200** so a real permission denial is never retried.
