## Data Inventory

### 1. Business Information (Prospect)

| Attribute | Detail |
|---|---|
| **What** | Business names, employee count, owner quoting status |
| **Why collected** | Core product — identifying and qualifying prospects |
| **Where stored** | Airtable (Prospects table), state.db (sessions), agent.log (tool output) |
| **Who has access** | James (Airtable owner), Atlas (Airtable API via PAT), DeepSeek (China) |
| **Leaves infrastructure?** | Yes — Airtable (US), DeepSeek (China) |
| **Third-party processors** | Airtable Inc., DeepSeek (China) |
| **Retention** | Indefinite (active), proposed: 12 months after lost, then anonymise |
| **Deletion process** | Manual Airtable record deletion. No automated purge. No backup purge. |
| **Legal considerations** | APP 3 (collection), APP 11 (security), APP 8 (cross-border — DeepSeek China) |

### 2. Personal Information — Contact Details

| Attribute | Detail |
|---|---|
| **What** | Contact first names, email addresses, phone numbers |
| **Why collected** | Primary contact channel for outreach and follow-up |
| **Where stored** | Airtable (Prospects, Clients, Quotes tables), state.db, agent.log, Gmail mailboxes |
| **Who has access** | James, Atlas (automated), DeepSeek (China) |
| **Leaves infrastructure?** | Yes — Airtable (US), Google Workspace (US/global), DeepSeek (China) |
| **Third-party processors** | Airtable Inc., Google Workspace, DeepSeek (China) |
| **Retention** | Indefinite. Proposed: Duration of engagement + 90 days for clients; 12 months for lost prospects |
| **Deletion process** | Manual only. Must also delete from state.db, agent.log, Gmail — no process exists |
| **Legal considerations** | APP 3, APP 5 (notification — now implemented via notices), APP 6 (use limitation), APP 7 (direct marketing opt-out — now implemented via notices), APP 11, APP 12 (access requests — no process) |
| **Minimisation** | Phone numbers collected for all prospects even when phone outreach not planned. Recommendation: collect only when phone outreach is planned. |

### 3. Location Data

| Attribute | Detail |
|---|---|
| **What** | Suburbs (and implicitly addresses in quote PDFs) |
| **Why collected** | Service area context for outreach and quote follow-up |
| **Where stored** | Airtable (Prospects, Quotes tables), quote PDFs in Gmail (quotes@) |
| **Who has access** | James, Atlas (automated), DeepSeek (China) |
| **Leaves infrastructure?** | Yes — Airtable (US), Google Workspace (US/global), DeepSeek (China) |
| **Third-party processors** | Airtable Inc., Google Workspace, DeepSeek (China) |
| **Retention** | Indefinite. Proposed: 24 months for quote data, then anonymise to suburb-level only |
| **Deletion process** | Manual. Quote PDFs in Gmail require mailbox-level deletion — no process. |
| **Legal considerations** | APP 3, APP 11. Full addresses in PDFs may be sensitive for sole traders operating from home. |
| **Minimisation** | Suburb is often sufficient. Full addresses in quote PDFs should be reviewed. |

### 4. Financial Information

| Attribute | Detail |
|---|---|

| **Why collected** | Core product — quote follow-up and business intelligence |
| **Where stored** | Airtable (Quotes, Clients tables), state.db, agent.log |
| **Who has access** | James, Atlas (automated), DeepSeek (China) |
| **Leaves infrastructure?** | Yes — Airtable (US), DeepSeek (China) |

| **Deletion process** | Manual only |

| **Minimisation** | Essential for product function. No reduction possible. |

### 5. Communication Records

| Attribute | Detail |
|---|---|
| **What** | Email bodies, outreach notes, message records, conversation state, relationship memory |
| **Why collected** | Operational record. Sales context. AI follow-up context. |
| **Where stored** | Gmail (atlas@, quotes@, james@), Airtable (Messages, Prospects.Outreach notes, Clients.Relationship memory, Quotes.Conversation state), state.db (all sessions), agent.log (tool output) |
| **Who has access** | James, Atlas (Gmail via OAuth, Airtable via PAT), DeepSeek (China) |
| **Leaves infrastructure?** | Yes — Google Workspace (US/global), Airtable (US), DeepSeek (China) |
| **Third-party processors** | Google Workspace, Airtable Inc., DeepSeek (China) |
| **Retention** | Indefinite everywhere. Proposed: 90 days state.db, 30 days agent.log, 24 months Airtable Messages |
| **Deletion process** | No process for state.db or agent.log. Manual for Airtable and Gmail. |
| **Legal considerations** | APP 11 (security — world-readable state.db until 2026-07-25). APP 12 (access requests would require manual assembly from 4+ systems). |
| **Minimisation** | state.db is 3.9GB — largest single PII store. 90-day retention would reduce to ~500MB. |

### 6. Quote Attachments

| Attribute | Detail |
|---|---|
| **What** | Quote PDFs — may contain full business names, addresses, ABNs, phone numbers, pricing, scope of work |
| **Why collected** | Quote intake pipeline — extracting structured data for follow-up |
| **Where stored** | Gmail (quotes@ mailbox), extracted text in Airtable (Quotes.Scope Summary Text), temporary files in /tmp during processing |
| **Who has access** | James, Atlas (quotes_token.json — OAuth to quotes@), DeepSeek (China) |
| **Leaves infrastructure?** | Yes — Google Workspace (US/global), Airtable (US), DeepSeek (China) |
| **Third-party processors** | Google Workspace, Airtable Inc., DeepSeek (China) |
| **Retention** | Indefinite in Gmail. Extracted text indefinite in Airtable. /tmp files temporary. |
| **Deletion process** | No automated deletion for Gmail or Airtable. /tmp cleared on reboot. |
| **Legal considerations** | APP 11 (PDFs may contain full personal information of customers' customers). Potentially notifiable data if breached. |
| **Minimisation** | Extract only needed fields. Do not retain full PDF text in Airtable if scope summary is sufficient. Delete /tmp extracts immediately after processing. |

### 7. Analytics & Tracking

| Attribute | Detail |
|---|---|
| **What** | Email open events (timestamp), website visitor data (GA4) |
| **Why collected** | Email engagement measurement (open tracking pixel), website analytics |
| **Where stored** | Airtable (Prospects.Last opened date, Open count), Vercel serverless logs, Google Analytics (GA4 property 502899171) |
| **Who has access** | James, Atlas, Google (GA4), Vercel |
| **Leaves infrastructure?** | Yes — Airtable (US), Vercel (US), Google Analytics (US/global) |
| **Third-party processors** | Airtable Inc., Vercel Inc., Google (Analytics) |
| **Retention** | Airtable: indefinite. GA4: 14 months (default). Vercel logs: unknown. |
| **Deletion process** | GA4 auto-expires. Airtable manual. |
| **Legal considerations** | APP 5 (collection notification — email open tracking now disclosed via notices). Privacy Policy disclosure required. |
| **Minimisation** | Tracking pixel is legitimate product feature. Privacy Policy disclosure required. |

### 8. AI Memory & Learning

| Attribute | Detail |
|---|---|
| **What** | memory/MEMORY.md — summarised business facts, preferences, corrections. learnings/LEARNINGS.md — bug fixes, may reference client scenarios indirectly |
| **Why collected** | System improvement. Cross-session continuity. |
| **Where stored** | /root/.hermes/memory/, /root/.hermes/learnings/ |
| **Who has access** | Atlas, (backed up to GitHub — private repo) |
| **Leaves infrastructure?** | Yes — GitHub (US) via nightly backup |
| **Third-party processors** | GitHub (Microsoft) |
| **Retention** | Indefinite |
| **Deletion process** | Git history contains all versions. Full purge requires git filter-branch. |
| **Legal considerations** | Memory entries are summaries, should not contain raw PII. Current practice appears compliant. |
| **Minimisation** | Continue current practice — summarise, never store raw PII in memory/learnings. |
